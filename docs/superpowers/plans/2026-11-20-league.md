# League Play Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Mark Castelluccio, written with Claude Code (AI-assisted).

**Goal:** An optional league: part of each generation's self-play is the current network against league members (random-move bot at first, later earlier networks), and a beaten member is replaced by the network that beat it.

**Architecture:** Records gain a per-move policy mask so opponent moves train value/reward/dynamics but not policy. Self-play gains a second entry point that plays the learner against per-game opponents (a second Model or the random bot) in the same lockstep batching. The trainer owns the league state, splits each generation's games, applies the replacement rule, and persists the league in state.bin.

**Tech Stack:** C++17, CMake, the repo's own test harness (one executable per tests/test_*.cpp, run by ctest).

**Spec:** docs/superpowers/specs/2026-11-20-league-design.md

## Global Constraints

- `league_size = 0` (the default) must leave every output bit-identical to today: same self-play records, same log.csv columns, same state.bin contents apart from the version field.

- Determinism: results must not depend on `workers`. Every random choice comes from seeds derived with `deriveSeed`, never from a generator carried across generations.
- Old files still load: replay buffer version 1 (masks empty = all ones) and state.bin version 1 (league empty). Bump versions; refuse unknown versions as now.

## Review Focus

1. A league game where the learner is White: its policy mask must be 1 at odd positions only.
2. A game the move cap truncated against the random bot (random games run long): the mask must still line up with positions, and the cap handling in fillSample must be unchanged.
3. Resume in the middle of a league run must reproduce an uninterrupted run byte for byte (league state, log rows, checkpoints).
4. A league member whose checkpoint file is missing on resume: a clear std::runtime_error naming the file.
5. `league_fraction` giving 0 league games (small games_per_generation): no division by zero, no league columns broken, no replacement.

### Task 2: League games in self-play

**Files:**
- Modify: `include/mzgo/selfplay.hpp`, `src/selfplay.cpp`
- Test: `tests/test_selfplay.cpp`

**Interfaces:**
- Consumes: Task 1's `GameRecord::policyMask`.
- Produces:
```cpp
// A league opponent: a network that plays MuZero search with the self-play
// settings (noise and temperature as for the learner), or, when model is
// null, the random-move bot (RandomPlayer).
struct LeagueOpponent { const Model* model = nullptr; };

// Game i plays the learner against opponents[opponentOf[i]]; the learner is
// Black when i is even. Every record's policyMask is 1 at the learner's
// positions and 0 at the opponent's. A bot move records a uniform-zero policy
// row and root value 0. Same seeding and worker-independence guarantees as
// playSelfPlay (game i draws from Rng(deriveSeed(seed, i))). Games sharing an
// opponent are batched in lockstep groups of cfg.group; the learner's and a
// network opponent's searches are batched separately, each through its own
// session. All models must agree on dims(), history() and passPlane() (asserted).
std::vector<GameRecord> playLeagueGames(const Model& learner, const std::vector<LeagueOpponent>& opponents,
                                        const std::vector<int>& opponentOf, const SelfPlayConfig& cfg,
                                        uint64_t seed, int workers, SelfPlayStats* stats = nullptr);
```
- `SelfPlayStats` over league games: the same fields, with mean depth and past-end averaged over the learner's searches only.
- `playSelfPlay`'s behavior and output must not change (refactor shared code if useful, but its records stay bit-identical; the existing tests pin this).

- [ ] **Step 1: Write failing tests** (FakeModel from tests/fake_model.hpp):
  - `test_league_random_opponent_masks`: 6 games vs one random-bot opponent; in every record, policyMask[p] == 1 exactly when (p % 2 == 0) == (game index even); every bot position's policy row sums to 0; every learner position's row sums to 1.
  - `test_league_random_bot_never_passes_early`: in those games, every move at an opponent position is a non-pass unless the bot had no other legal move (replay the game and check `legalActions()`).
  - `test_league_network_opponent_used`: learner and opponent are FakeModels whose root hooks put all prior mass on different fixed points; with temperature off and noise off, the learner's moves and the opponent's moves follow their own model.
  - `test_league_workers_independent`: 10 games over two opponents (one null, one network), workers 1 and 3 give identical records.
- [ ] **Step 2: Run them, see them fail.**
- [ ] **Step 3: Implement.** Sort game indices by opponent before cutting groups so each group has one opponent; inside a group, each step partitions live games by whose turn it is.

### Task 3: League in the trainer, config, state and docs

**Files:**

- Create: `include/mzgo/league.hpp`, `src/league.cpp` (add to CMake like the other sources)
- Test: `tests/test_league.cpp` (new, registered like the others), `tests/test_config.cpp`, `tests/test_trainer.cpp`

**Interfaces:**
- Consumes: Task 2's `playLeagueGames`, `LeagueOpponent`.
- Config keys (RunConfig fields in parentheses), parsed like the existing int/float keys:
  - `league_size` (leagueSize, int, default 0, valid 0..8)
  - `league_fraction` (leagueFraction, float, default 0.5, valid [0, 1])
  - `league_replace_score` (leagueReplaceScore, float, default 0.55, valid [0, 1])
  - `league_min_games` (leagueMinGames, int, default 20, valid ≥ 0)
  - `league_size` cannot change on resume (same error style as architecture keys, but it is not added to `architectureKeys()`, which is about tensor shapes).
- `include/mzgo/league.hpp`:
```cpp
// One slot: the random-move bot (generation = -1) or the network saved as checkpoints/gen_GGGG.mzn.
struct LeagueMember { int generation = -1; bool isRandom() const { return generation < 0; } std::string name() const; /* "random" or "gen_N" */ };
struct LeagueResult { int games = 0; double points = 0; double score() const; /* points / games, 0 if none */ };
// Number of league games this generation: round(gamesPerGeneration * fraction), 0 when size == 0.
int leagueGameCount(int gamesPerGeneration, float fraction, int size);
// Per-member results from league records (learner Black in even games; win 1, draw 0.5, loss 0).
std::vector<LeagueResult> leagueResults(const std::vector<GameRecord>& leagueGames, const std::vector<int>& opponentOf, int members);
// The slot to replace: among members with games >= minGames and score() >= threshold, the highest score; ties go to the lowest slot; -1 if none.
int chooseReplacement(const std::vector<LeagueResult>&, double threshold, int minGames);
```
- Trainer generation g with league_size > 0:
  1. S = gamesPerGeneration − L ordinary self-play games, seed `deriveSeed(seed, g, 1)` (unchanged), then L league games, seed `deriveSeed(seed, g, 4)`, `opponentOf[j] = j % leagueSize`. Network members are loaded from their checkpoints (std::runtime_error naming the file if missing).
  2. Replay gets the S self-play records, then the L league records.
  3. After training, before `writeState()`: `slot = chooseReplacement(...)`; if slot ≥ 0, `league_[slot] = {g - 1}`.
  4. log.csv: when league_size > 0 only, three columns are appended to the header and to every row: `league_members` (names joined by `;`, after any replacement), `league_scores` (the generation's scores per slot before replacement, `;`-joined, empty field for a member with 0 games), `league_replaced` (slot or -1). The other columns' statistics cover all games.
  5. Summary line: when league_size > 0 append `, league random 0.42 | gen_12 0.5 | random 0.3` and, when a slot was replaced, `, slot 0 -> gen_14`.
  6. SGF: also the first sgf_per_generation league games, as `sgf/gen_GGGG_league_I.sgf`.
  7. A new run starts with league_size random members.
- state.bin version 2: the existing fields, then u32 member count and an i32 generation per member. Version 1 loads with an empty league; a loaded league whose size differs from league_size is a runtime_error.
