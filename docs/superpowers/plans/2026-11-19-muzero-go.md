# MuZero Go Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A from-scratch C++17 MuZero (board-game configuration of the paper) for Go on 5×5 and 9×9, with diagnostics that look inside the learned model.

**Architecture:** `alphazero-go`'s foundation (rules, encoding, layers with hand-written backward, naive/BLAS backend, thread pool, serialization, SGD) is copied into namespace `mzgo`. New code: the three MuZero functions with backprop through the K-step unroll, a pseudocode-faithful search behind a `Model` interface, replay/targets, batched-lockstep self-play, a synchronous generation loop, arena/bots/GTP, and probe tools.

**Tech Stack:** C++17, CMake ≥ 3.16, optional BLAS (Accelerate / OpenBLAS), assert-based CTest executables, Python 3 standard library for `tools/gtp_match.py`.

**Spec:** `docs/superpowers/specs/2026-11-19-muzero-go-design.md` (read it before any task; section names below refer to it).

## Global Constraints

- C++17; no third-party libraries except optional BLAS. Namespace `mzgo`; headers `include/mzgo/*.hpp`, sources `src/*.cpp`, programs `apps/*.cpp` (executables prefixed `mzgo_`), tests `tests/test_*.cpp`.
- CMake option `MZ_USE_BLAS` (default OFF), defining `MZ_USE_BLAS`; library target `mzgo`. Sources, apps and tests are discovered by `file(GLOB ... CONFIGURE_DEPENDS)`; no task edits `CMakeLists.txt` except Task 1.
- Tests compile with `-UNDEBUG` and get `MZGO_SOURCE_DIR`; a test is one executable of `static void test_x()` functions called from `main`, printing `test_<name>: OK`.
- All randomness via `mzgo::Rng` / `deriveSeed`; results must not depend on worker or thread counts.
- The real game is consulted only at the search root (observation + legal mask) and to play the chosen move. Never below the root.
- Hidden state layout at every interface: sample-major `[B][filters][area]` floats. Layers internally are channel-major `[C][B][area]`.
- Action indices: point = row·n + col, pass = n² (`Board::passAction()`); `actions = n² + 1`.
- Paper constants: c1 = 1.25, c2 = 19652, discount 1, known bounds [−1, 1], noise fraction 0.25, K = 5, hidden-gradient scale 0.5, loss scale 1 at k = 0 and 1/K at k ≥ 1, momentum 0.9, weight decay 1e-4, min-max denominator floor 1e-5.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Files copied from `alphazero-go` keep a header line `// Copied from alphazero-go (Mark Castelluccio), adapted for mzgo.`
- Build dirs: each parallel worker uses its own (`build-<task>`), configured with `-DCMAKE_BUILD_TYPE=Release -DMZ_USE_BLAS=ON`.

## Review Focus

1. A game shorter than K, or a sampled position within K of the end, or a game ended by the move cap: targets must pad with absorbing steps (value 0, policy masked, random actions) without reading past arrays. → Task 4 test `test_short_game_padding`.
2. A hidden state with max == min (e.g. a dead ReLU stem at init): normalization must produce finite values and finite gradients. → Task 3 test `test_minmax_constant_input`.
3. A root where pass is the only legal move: search must put every visit on pass and still return a valid result. → Task 5 test `test_single_legal_root`.
4. Resuming with a changed architecture key, or a corrupt / truncated `state.bin` or checkpoint: refuse with a message naming the key or file, never train from garbage. → Task 9 tests `test_resume_refuses_arch_change`, `test_corrupt_checkpoint`.
5. A NaN/inf loss during training: stop the run with an error naming the generation and step, before writing a checkpoint. → Task 9 test `test_nan_loss_stops`.

Training forward (one sample batch, k = 0..K):
s⁰ = norm(h(obs)); (p⁰, v⁰) = f(s⁰); for k = 1..K: x = concat(sᵏ⁻¹, actionPlane(a_k)) with the action plane all zeros except 1 at the stone point (pass: all zeros); sᵏ = norm(g(x)); rᵏ = rewardHead(sᵏ) if enabled; (pᵏ, vᵏ) = f(sᵏ).
Loss per k: CE(πₖ, softmax pᵏ)·maskₖ + (zₖ − vᵏ)² (+ (uₖ − rᵏ)² for k ≥ 1 with reward head), batch mean, times scale (1 at k = 0, 1/K after).
Backward runs k = K..1: gradient into sᵏ⁻¹ = (from f at k−1) + **0.5 ×** (the first F channels of dx of g at k); the action plane's gradient is discarded. The reward head reads the hidden state after normalization (design: "dynamics → (sᵏ, rᵏ)" — my reading; record it in a code comment).

```cpp
public:
```

```cpp
struct LeafRequest { const float* parentHidden; int action; };
struct SearchResult {

public:

                   const std::vector<int>& legal, bool previousMoveWasPass, Rng& rng);
    bool finished() const;              // simulations done
    LeafRequest selectLeaf();           // descends from the root; asserts !finished()
    void expandLeaf(const float* hidden, const float* logits, float value, float reward);
    SearchResult result() const;
    int selectMove(const SearchResult&, bool sample, Rng& rng) const;  // sample ∝ visits, else argmax (ties: lowest index)
};
// Convenience for one game, batch 1: begin + loop of select/recurrentInference/expand.
SearchResult runSearch(Search&, ModelSession&, const Game& game, int history, Rng& rng);
```

Rules (spec "Search"): score = Q̄ + P·√N_parent/(1+N_child)·(c1 + log((N_parent + c2 + 1)/c2)); Q̄ = normalize(r + γ·(−v_child)) for visited children, 0 for unvisited; ties broken by larger prior, then lower action (my call, spec's first-simulation note). The root's own value is not backed up (pseudocode). Backup: leaf value v at leaf; walking up, each node adds the value from its own to-play view (negate per ply) and `minmax.update(r + γ·(−v_child))` per edge. Children of non-root nodes: all `actions`, prior = softmax(logits), unmasked.
